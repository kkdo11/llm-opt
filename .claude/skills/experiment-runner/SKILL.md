# 실험 설계 및 결과 기록

## 목적
LLM-OPT의 성능 검증을 위한 실험을 체계적으로 설계하고 결과를 기록한다.

## 실험 설계 템플릿

모든 실험은 다음 구조를 따른다:

```python
"""
실험명: {명확한 실험 이름}
Phase: {해당 Phase}
날짜: {YYYY-MM-DD}

가설: {검증하려는 가설을 한 문장으로}

독립 변수: {변경하는 것}
종속 변수: {측정하는 것}
통제 변수: {고정하는 것}

테스트 데이터:
  - 크기: {N개}
  - 구성: {중복 비율, 질문 유형 등}
  - 생성 방법: {수동 작성 / GPT 생성 / 실제 로그}

성공 기준:
  - {기준 1}: {구체적 수치}
  - {기준 2}: {구체적 수치}
"""
```

## 결과 기록 형식

```python
"""
실험 결과:
  환경: {Python 버전, Redis 버전, 하드웨어 등}
  실행 시간: {총 소요 시간}
  
  결과:
    | 조건 | {측정1} | {측정2} | {측정3} |
    |------|---------|---------|---------|
    | A    |         |         |         |
    | B    |         |         |         |
  
  결론: {가설 검증 결과}
  예상과의 차이: {예상했던 것과 실제 차이, 그 이유}
  다음 단계: {이 결과를 바탕으로 할 일}
"""
```

## 핵심 실험 목록 (LLM-OPT)

### Phase 1
- Hash Cache Hit Ratio 측정 (중복률 50% 테스트셋)

### Phase 2
- Similarity Threshold 비교 (0.75 / 0.80 / 0.85 / 0.90)
- Validation Layer 유무에 따른 False Positive 비교
- Embedding 모델 선택 (all-MiniLM-L6-v2 vs 대안)

### Phase 3
- 출력 토큰 예측 정확도 측정
- 비용 폭탄 시나리오 차단율 측정

### Phase 4
- 이동 평균 vs 순간값 기반 HPA 비교
- k6 부하 테스트 시나리오별 결과

### Phase 5
- 비용 예측 정확도 (예측 vs 실제)

## 주의사항
- IMPORTANT: 실험 결과는 재현 가능해야 함. 환경 정보를 반드시 기록.
- 결과가 예상과 다르면 "왜 다른지" 분석을 반드시 추가.
- 유리한 결과만 기록하지 말고, 실패한 실험도 기록 (면접에서 더 가치 있음).
