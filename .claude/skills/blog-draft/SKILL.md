# 기술 블로그 초안 작성

## 목적
LLM-OPT 프로젝트 진행 중 발생한 트러블슈팅 경험, 기술적 발견을 kdw.tistory.com 스타일의 블로그 포스트로 변환한다.

## 블로그 포스트 구조

도원이의 기존 블로그 스타일을 따른다:

```markdown
# {제목: 구체적이고 검색 가능한 제목}

## 문제 상황
- 어떤 작업을 하다가 문제를 발견했는지
- 에러 메시지 또는 증상을 구체적으로 기술
- 재현 환경 (Python 버전, Redis 버전 등)

## 원인 분석
- 처음에 어떻게 원인을 추적했는지
- 로그, 메트릭, 디버깅 과정
- 근본 원인이 무엇이었는지

## 시도한 해결책들
### 시도 1: {방법}
- 무엇을 했는지
- 결과: 성공/실패 + 이유

### 시도 2: {방법}
- (반복)

## 최종 해결
- 어떤 방법으로 해결했는지
- 핵심 코드 또는 설정 변경
- 해결 후 측정 결과 (있다면)

## 배운 점
- 이 경험에서 얻은 교훈
- 다음에는 어떻게 할 것인지
- 관련 공식 문서나 참고 자료 링크
```

## 작성 규칙

- 한국어로 작성, 기술 용어는 영어 원문 유지
- 코드 블록에는 반드시 언어 표시 (```python, ```yaml 등)
- "예상" vs "실측" 구분 명확하게
- 과장 없이 사실 기반
- 독자가 같은 문제를 만났을 때 바로 따라할 수 있도록 구체적으로
- SEO를 고려한 제목 (예: "Redis Vector Search HNSW Index 생성 시 OOM 해결기")

## 블로그 소재 감지

다음 상황이 발생하면 블로그 소재로 표시:
- 에러가 발생하고 해결하는 데 30분 이상 걸린 경우
- 공식 문서와 다르게 동작한 경우
- 성능 측정 결과가 예상과 크게 다른 경우
- 기술 선택에서 흥미로운 Trade-off가 있는 경우

표시 형식:
```
📝 [블로그 소재] {한 줄 요약}
상세: {문제와 해결 과정 요약}
```

소재가 감지되면 docs/PHASE_TRACKER.md의 "블로그 소재" 섹션에 기록한다.
